# 代理原生架構稽核

對碼庫執行全面之代理原生架構原則審查，為每項原則啟動並行子代理，產出評分報告。

## 待稽核之核心原則

1. **行動對等** - "用戶能做之事，代理亦能做"
2. **工具即原語** - "工具提供能力，非行為"
3. **上下文注入** - "系統提示包含應用狀態之動態上下文"
4. **共享工作區** - "代理與用戶操作同一資料空間"
5. **CRUD 完整性** - "每個實體皆有完整 CRUD（建立、讀取、更新、刪除）"
6. **UI 整合** - "代理操作即時反映於 UI"
7. **能力發現** - "用戶能發現代理可做之事"
8. **提示原生特性** - "特性即提示，定義結果，非碼"

## 工作流

### 步驟一：載入代理原生技能

首先調用 agent-native-architecture 技能以理解所有原則：

```
/ce-agent-native-architecture
```

選擇選項 7（行動對等）以載入完整參考資料。

### 步驟二：啟動並行子代理

以 Task 工具搭配 `subagent_type: Explore` 啟動 8 個並行子代理，每項原則一個。各代理應：

1. 列舉碼庫中所有實例（用戶操作、工具、上下文、資料存儲等）
2. 對照原則檢查合規性
3. 提供具體評分如 "X 分之 Y（百分比%）"
4. 列出具體缺口及建議

<sub-agents>

**代理一：行動對等**
```
稽核行動對等——「用戶能做之事，代理亦能做。」

任務：
1. 列舉前端中所有用戶操作（API 呼叫、按鈕點擊、表單提交）
   - 搜尋 API 服務檔、fetch 呼叫、表單處理器
   - 檢查路由及元件中的用戶互動
2. 檢查哪些有對應之代理工具
   - 搜尋代理工具定義
   - 將用戶操作映射至代理能力
3. 評分：「代理能做 Y 項用戶操作中之 X 項」

格式：
## 行動對等稽核
### 發現之用戶操作
| 操作 | 位置 | 代理工具 | 狀態 |
### 評分：X/Y（百分比%）
### 缺失之代理工具
### 建議
```

**代理二：工具即原語**
```
稽核工具即原語——「工具提供能力，非行為。」

任務：
1. 尋找並讀取所有代理工具檔
2. 各工具分類為：
   - 原語（佳）：read、write、store、list——提供能力不含業務邏輯
   - 工作流（劣）：編碼業務邏輯、做決策、編排步驟
3. 評分：「Y 工具中有 X 為正確原語」

格式：
## 工具即原語稽核
### 工具分析
| 工具 | 檔案 | 類型 | 理由 |
### 評分：X/Y（百分比%）
### 問題工具（應為原語之工作流）
### 建議
```

**代理三：上下文注入**
```
稽核上下文注入——「系統提示包含應用狀態之動態上下文」

任務：
1. 尋找上下文注入碼（搜尋 "context"、"system prompt"、"inject"）
2. 讀取代理提示及系統訊息
3. 列舉已注入與應注入之內容：
   - 可用資源（檔案、草稿、文檔）
   - 用戶偏好/設定
   - 近期活動
   - 已列可用能力
   - 會話歷史
   - 工作區狀態

格式：
## 上下文注入稽核
### 上下文類型分析
| 上下文類型 | 已注入？ | 位置 | 備註 |
### 評分：X/Y（百分比%）
### 缺失上下文
### 建議
```

**代理四：共享工作區**
```
稽核共享工作區——「代理與用戶操作同一資料空間」

任務：
1. 識別所有資料存儲/表/模型
2. 檢查代理是否讀寫相同表或分離表
3. 尋找沙盒隔離反模式（代理有獨立資料空間）

格式：
## 共享工作區稽核
### 資料存儲分析
| 資料存儲 | 用戶存取 | 代理存取 | 共享？ |
### 評分：X/Y（百分比%）
### 隔離資料（反模式）
### 建議
```

**代理五：CRUD 完整性**
```
稽核 CRUD 完整性——「每個實體皆有完整 CRUD」

任務：
1. 識別碼庫中所有實體/模型
2. 各實體檢查是否存在代理工具：
   - 建立
   - 讀取
   - 更新
   - 刪除
3. 各實體及整體評分

格式：
## CRUD 完整性稽核
### 實體 CRUD 分析
| 實體 | 建立 | 讀取 | 更新 | 刪除 | 評分 |
### 整體評分：X/Y 實體具完整 CRUD（百分比%）
### 不完整實體（列出缺失操作）
### 建議
```

**代理六：UI 整合**
```
稽核 UI 整合——「代理操作即時反映於 UI」

任務：
1. 檢查代理寫入/變更如何傳播至前端
2. 尋找：
   - 串流更新（SSE、WebSocket）
   - 輪詢機制
   - 共享狀態/服務
   - 事件匯流排
   - 檔案監控
3. 識別「靜默操作」反模式（代理變更狀態但 UI 未更新）

格式：
## UI 整合稽核
### 代理操作 → UI 更新分析
| 代理操作 | UI 機制 | 即時？ | 備註 |
### 評分：X/Y（百分比%）
### 靜默操作（反模式）
### 建議
```

**代理七：能力發現**
```
稽核能力發現——「用戶能發現代理可做之事」

任務：
1. 檢查此 7 種發現機制：
   - 展示代理能力之引導流程
   - 說明文檔
   - UI 中之能力提示
   - 代理於回應中自述
   - 建議提示/操作
   - 空狀態指引
   - 斜線指令（/help、/tools）
2. 對 7 種機制評分

格式：
## 能力發現稽核
### 發現機制分析
| 機制 | 存在？ | 位置 | 品質 |
### 評分：X/7（百分比%）
### 缺失發現
### 建議
```

**代理八：提示原生特性**
```
稽核提示原生特性——「特性即提示，定義結果，非碼」

任務：
1. 讀取所有代理提示
2. 各特性/行為分類為定義於：
   - 提示（佳）：以自然語言定義結果
   - 碼（劣）：業務邏輯硬編碼
3. 檢查行為變更需改提示還是改碼

格式：
## 提示原生特性稽核
### 特性定義分析
| 特性 | 定義於 | 類型 | 備註 |
### 評分：X/Y（百分比%）
### 碼定義特性（反模式）
### 建議
```

</sub-agents>

## 成功準則

- [ ] 所有 8 個子代理完成其稽核
- [ ] 每項原則有具體數字評分（X/Y 格式）
- [ ] 摘要表顯示所有評分及狀態指標
- [ ] 影響力前十大建議按影響力排序
- [ ] 報告識別優勢及缺口

## 可選：單一原則稽核

若 $ARGUMENTS 指定單一原則（如 "action parity"），僅執行該子代理並提供該原則之詳細發現。

有效參數：
- `action parity` 或 `1`
- `tools` 或 `primitives` 或 `2`
- `context` 或 `injection` 或 `3`
- `shared` 或 `workspace` 或 `4`
- `crud` 或 `5`
- `ui` 或 `integration` 或 `6`
- `discovery` 或 `7`
- `prompt` 或 `features` 或 `8`
